# Memo · 酒馆版 1.0.26

安装地址：https://github.com/cszgezi-lab/Memo-ST

支持 SillyTavern 1.17.x–1.19.x。扩展管理中安装后，打开 Memo 的设置，填写总结、动态人设、向量或重排连接，再按需要开启运行。与旧版拾忆使用独立存储、连接和安装地址；同一聊天请只启用其中一个版本。

设置中的标签管理可提取或排除 XML 等正文块，不修改聊天原文。日志页提供日志、配置及当前聊天备份导出；API Key 不进入备份。存档按当前站点、浏览器、账户和聊天隔离。更换浏览器、设备或站点前，请导出需要的聊天备份。

实际记忆注入和动态人设替换支持 Chat Completion。文本生成接口保留原设定，可整理、管理和预览记忆。总结、人设和模型列表使用酒馆认证转发；向量、重排及非标准接口路径需服务允许浏览器 CORS。

浏览器下载提示只表示已派发，请确认文件实际保存。真实模型语义和 Android 实机效果需要分别验收。

主总结、修复复核及动态人设采用流式传输，收到完整回复并通过原有校验后才保存；中断和错误不会作为成功结果落地。已知渠道错误会尽早结束等待，恢复仍受现有次数上限、限流与冷却约束。主总结预设新增“破甲区”：反截断开关和可编辑破甲词；头部及用户输入长填充可选，默认关闭；旧版遗留的开启值不会自动生效，需在破甲区重新开启并保存。两项全开约增加2.2万字符/次。破甲词计入预算，工具参数与记忆完整性仍严格校验；这些选项不能保证解决服务商截断或限流。兼容工具及填充文本的 MIT 署名见 LICENSE.txt。

1.0.16：完整总结 JSON 可在渠道漏发结束标记时继续校验保存；真实截断、长度限制和内容拦截分别处理。同步清理未执行的不足整批空尾项，事件合并本地收尾，无法合并的有效记录独立保留，不增加模型请求。

1.0.17：传输失败时在日志保留最多8192字符的响应首尾原文、实际长度和结束状态，已遮蔽已知Key和凭据字段；日志及完整排障包均可导出。只截取既有响应，不增加请求，成功回复不记录原文。
